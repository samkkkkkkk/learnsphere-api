🚀 Choosing The State Structure 마스터하기 (중급)

📘 Core Concepts

상태를 효율적으로 구조화하는 것은 React 컴포넌트를 설계할 때 매우 중요합니다. 잘 구조화된 상태는 코드의 복잡성을 줄이고, 버그를 방지하며, 디버깅을 용이하게 합니다. 아래는 상태 구조화에서 고려해야 할 몇 가지 핵심 원칙입니다:

1. 연관된 상태 그룹화하기: 두 개 이상의 상태 변수가 항상 동시에 업데이트될 때는 이들을 단일 상태 변수로 통합하는 것이 좋습니다. 이는 동기화를 유지하는 데 유리합니다. 2. 상태의 모순 피하기: 여러 상태 조각이 서로 불일치하는 방식으로 구성되면 혼란이 생길 수 있으니, 한 상태로 통합하거나 관련된 상태를 그룹화하는 것이 중요합니다. 3. 불필요한 상태 피하기: 렌더링 중 컴포넌트의 props나 기존 상태에서 값을 계산할 수 있다면, 그 값을 별도로 상태로 유지할 필요가 없습니다. 4. 상태의 중복 피하기: 동일한 데이터 조각이 여러 상태 변수에 중복될 경우, 동기화를 관리하기 어려워지므로 중복을 피해야 합니다. 5. 깊게 중첩된 상태 피하기: 깊게 중첩된 상태는 업데이트하기 어렵고, 코드의 가독성을 떨어뜨리므로 평탄한 구조로 만드는 것이 좋습니다.

이러한 원칙들을 지킴으로써 오류 없이 상태를 쉽게 업데이트하고, 컴포넌트를 효율적으로 관리할 수 있습니다.

📝 Quiz

1. 문제: 두 개의 상태 변수가 항상 동시에 변경될 때, 이를 어떻게 구조화하는 것이 좋을까요?

정답: 두 개의 상태 변수를 단일 상태 변수로 통합하여 그룹화하는 것이 좋습니다. 이는 동기화를 유지하고 관리하기 용이하게 합니다.

2. 문제: 상태에서 중복된 정보를 피해야 하는 이유는 무엇인가요?

정답: 상태에서 중복 정보를 피해야 하는 이유는 동기화 관리가 어려워지고, 버그 발생 가능성이 커지기 때문입니다. 중복을 줄이면 변경 사항을 쉽게 추적할 수 있습니다.

3. 문제: 깊게 중첩된 상태를 구성할 경우의 문제점은 무엇인가요?

정답: 깊게 중첩된 상태는 업데이트하기 어렵고, 가독성을 떨어뜨리며, 복잡한 구조를 초래하여 디버깅이 힘들어지기 때문에 평탄한 구조로 만드는 것이 좋습니다.
