🚀 You Might Not Need An Effect 마스터하기 (고급)

📘 Core Concepts

Effect는 컴포넌트를 외부 시스템과 동기화할 수 있는 강력한 도구지만, 모든 경우에 필요한 것은 아닙니다. 때로는 Effect가 불필요한 경우가 있으며, 이를 제거하면 코드의 가독성과 효율성이 향상됩니다. 불필요한 Effect를 제거하는 두 가지 일반적인 경우는 다음과 같습니다:

1. 렌더링을 위해 데이터를 변환하는 경우: 렌더링 중 필요한 데이터를 직접 계산하면, 매 렌더링 시점에서 최신 값을 얻을 수 있으며, 초기 렌더링 후 불필요한 Effect 호출을 피할 수 있습니다. 2. 사용자 이벤트를 처리하는 경우: 이벤트 핸들러에서 직접 상태를 변경함으로써, 사용자의 행동이 발생하는 즉시 반응하도록 만들 수 있습니다.

이러한 경우에 Effect를 사용하지 않으면 코드의 복잡성이 줄어들고, 성능 개선과 오류 가능성 감소로 이어집니다.

📝 Quiz

1. 문제: 렌더링 중에 데이터를 변환해야 할 때 Effect를 사용하는 것이 비효율적인 이유는 무엇인가요?

정답: Effect를 사용하면 상태 업데이트 후 추가 렌더링이 발생하므로 초기값으로 렌더링 후 다시 업데이트하게 되어 불필요한 성능 낭비가 발생한다.

2. 문제: 사용자 이벤트를 처리하기 위해 Effect를 사용하는 것의 단점은 무엇인가요?

정답: 이벤트 핸들러에서 직접 상태를 업데이트하는 것이 아니라 Effect를 사용하면 이벤트가 발생하는 시점과 Effect 실행 시점 간의 차이로 인해 데이터 동기화가 늦어져 잘못된 값을 사용할 수 있다.

3. 문제: 컴포넌트가 외부 데이터를 구독할 때 적절한 방법은 무엇인가요?

정답: 외부 데이터를 사용할 때는 Effect를 사용하여 구독하는 것이 적절하지만, React의 내장 Hook인 useSyncExternalStore를 사용하는 것이 더 안전하고 효율적이다.
