🚀 Separating Events From Effects 마스터하기 (고급)

📘 Core Concepts

이벤트 핸들러(event handler)는 사용자의 특정 상호작용, 예를 들어 버튼 클릭을 통해 수동으로 실행됩니다. 반면 Effect는 React의 상태나 prop이 변경될 때 자동으로 실행되어 동기화를 유지합니다.

이 두 가지는 중요한 차이점이 있습니다. 이벤트 핸들러에는 사용자가 같은 행동을 반복하지 않는 한 재실행되지 않는 비반응형 로직이 포함됩니다. 반면 Effect는 상태나 prop이 변경될 때마다 재시작되는 반응형 로직으로 구성됩니다.

때로는 Effect 내부에 비반응형 로직을 포함하고 싶을 수 있습니다. 이럴 때 useEffectEvent와 같은 특수한 Hook을 사용하여 비반응형 코드를 Effect 이벤트(event event)로 분리할 수 있습니다. 이를 통해 React는 해당 코드를 비반응형으로 취급하면서 항상 최근의 props와 state를 읽을 수 있습니다.

💻 Code Examples

import { useState, useEffect } from 'react';

import { experimental_useEffectEvent as useEffectEvent } from 'react'; import { createConnection, showNotification } from './notifications.js';


const serverUrl = 'https://localhost:1234';


function ChatRoom({ roomId, theme }) { const onConnected = useEffectEvent(connectedRoomId => { showNotification(connectedRoomId + '에 오신 것을 환영합니다', theme); });


useEffect(() => { const connection = createConnection(serverUrl, roomId); connection.on('connected', () => { onConnected(roomId); }); connection.connect(); return () => connection.disconnect(); }, [roomId]);

📝 Quiz

1. 문제: 이벤트 핸들러와 Effect의 가장 큰 차이점은 무엇인가요?

정답: 이벤트 핸들러는 특정 사용자 상호작용에 따라 실행되는 반면, Effect는 상태나 prop의 변경에 따라 자동으로 실행됩니다.

2. 문제: 비반응형 로직을 Effect에서 분리하려면 어떤 Hook을 사용해야 하나요?

정답: useEffectEvent Hook을 사용하여 비반응형 로직을 Effect 이벤트로 분리할 수 있습니다.

3. 문제: 예를 들어 chatRoom 컴포넌트에서 사용자가 방을 변경할 때마다 효과적으로 연결을 유지하기 위해 어떤 코드를 작성해야 할까요?

정답: useEffect를 사용하여 채팅방의 ID가 변경될 때마다 연결을 다시 설정하는 코드를 작성해야 합니다. 사용자가 여행 방으로 변경하면 연결이 자동으로 따릅니다.
